# WP-825 native source accounting under contention

Package: WP-825. Tier: guarantee, under accepted ADR-0279 and the standing
approval for necessary native fixes. WP-825 and WP-826 remain open.

## Problem and evidence

The fixed-schedule diagnostic at revision `6f35ed7e` stops near load second
2,900 because completed exact source-byte observations exceed the unchanged
95-second gap limit. Its earlier consumer and sink outages recover. All
completed load windows pass. Restore at second 5,400 is never reached.

The closed population and failure evidence are preserved. A focused native
test on a verified copy scans 275,313 newly eligible canonical receipts in
23.63 seconds without foreground load. Under public compiled commands and
named-query reads offered at 100 commands and 400 reads per second, it expires
at 30 seconds after 216,320 receipts. The contention diagnostic completes
24,000 fresh commands and 96,000 reads without retries, but reports latency
overflow; it does not qualify service levels or the campaign.

Removing repeated receipt serialization and decoding increases completed
work to 259,328 receipts before the same expiry. That candidate still fails.
A process-scoped CPU profile then attributes 30.36 percent of sampled user CPU
to namespace-to-table mapping, 32.89 percent to SHA-256 compression, and 5.86
percent to the indexed mutation sort. Receipt reconstruction repeatedly searches
the fixed catalog, including from the sort comparator.

These component diagnostics identify a real native capacity limitation. They
do not establish the sole cause of the original controller observation gap.
The optimized native test executable scans one copy while an unchanged shipping
server and a private diagnostic worker load another copy on the same host.
The diagnostic uses acknowledged existing ticket revisions and fresh compiled
writes; its historical reads do not supply a campaign freshness oracle.

## Resulting implementation

- Unbudgeted source point reads use the existing fully checked native receipt
  constructor. Inline receipts still use the complete canonical codec. Stub
  reads retain full frame validation and reconstruct the same typed receipt
  without serializing it merely to decode those generated bytes again.
- Exact accounting admits a row by its checked encoded length, then uses the
  existing single-encode history successor. It verifies the actual encoded
  length before adopting the successor or counters. The original 256-row and
  byte bounds, terminal check, lineage and source-chain checks remain.
- The sole catalog declaration generates direct table/key dispatch. Exact mixed
  metadata keys, unknown-table/key refusal, authority classes, canonical inventory
  and catalog identity are unchanged. No cache or extra provider charge is added.

The provider-admitted decode path, writer admission and rest, capture freshness,
95-second gap, durable formats, checksums, public operations and all workload
and fault gates remain unchanged. No fixture regeneration is needed.

## Validation and limits

The point-reader regression fails on the original implementation. It compares
both native point readers with the exact original receipt and checks that later
physical frame corruption is still refused. Existing accounting and cursor
checks, all 59 native architecture checks, and all-target Clippy pass on the required 8-vCPU, 32-GiB Linux SSD host.

The dispatch equivalence test compares every declared table against exact,
truncated, extended, empty, binary and unknown metadata keys using an independent
inventory walk. V1/V2 catalog tests and the frozen inventory pass. The loaded retest completes all 275,313 receipts in 28.00 seconds and finishes
24,000 commands plus 96,000 reads without retries. It still reports latency
overflow, and the unchanged shipping server emits no source-byte samples during
that four-minute cold-start diagnostic. This closes the reproduced component
scan expiry, not native-worker freshness or service-level qualification. The corrected server is then tested directly against the retained population,
without the extra scan process. It also emits no source-byte samples within
95 seconds. Its initial source validation checks 71,168 rows with no invalidations
or admission refusals; byte capture remains gated on the complete paced proof.
A separate guarantee review is required before decoupling read-only accounting
readiness from deletion authority. No such boundary change is implemented here.

Final-source scoped acceptance, full CI, the complete native worker's observation
freshness, fixed-schedule restore, the eight-hour rehearsal and the uninterrupted
24-hour qualification remain required. No success on this component may replace
them. The application interface and handbook operation remain unchanged;
[Sustainable TicketDesk](SUSTAINABLE-TICKETDESK.md) records qualification status.

Compatibility: unchanged canonical receipts, catalog identity, durable writer,
provider admission and public interfaces. Hazards and follow-ups: retained-source
scan cost and observation scheduling must still be measured in the actual native
worker, and the tighter 45-second restore release remains unproven.
