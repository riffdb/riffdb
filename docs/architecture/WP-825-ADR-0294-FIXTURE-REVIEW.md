## Evidence and limits

All checks run on the required 8-vCPU, 32-GiB Linux host with durable SSD storage.
A corrected missing-encoder baseline fails with the expected typed format error,
then four codec/compatibility tests pass. The earlier invalid synthetic UUID
attempts are retained as failed setup evidence and prove no codec behavior.

A genuine native reader is compiled and frozen before its production receipt
inventory implementation learns the new suffixes. The manifest records that
exact source and executable hash. Executing its retained test binary against the
Prepared vector and each new record/temporary filename refuses `CorruptData`.
The configured media, ordinary receipt temporary and unadmitted stage evidence
remain byte-identical. This proves old-reader refusal before cleanup or database
open; it does not prove the new protocol's ownership, publication or recovery.

Current native tests also reject every truncation, checksum corruption, resealed
unknown version/phase, reordered/duplicate/extra artifact kind, trailing field,
conflicting database/incarnation/frontier and nonmonotone phase transition.
A separate check compares all three frozen vectors with their exact native
encoding and decoded bindings. Fixture and final-source checks remain distinct.

The existing receipt, backup, journal, registry, catalog and format-marker
fixtures are unchanged. These new intent vectors have their own closed manifest;
production transfer is not enabled by this codec checkpoint. Its integration,
crash cuts, publication verification, saved 60-second gate, actual scheduled
fault windows and final-source CI remain pending. Neither campaign has started.
